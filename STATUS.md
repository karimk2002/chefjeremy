## How to run the site
```
cd site
npm install
npm run dev            # http://localhost:4321 (also .claude/launch.json → "jeremygillon-dev")
npm run check          # astro check + check-copy + grade-check
npm run sync:copy      # regenerate src/content/copy.yaml from ../CONTENT.md (after editing CONTENT.md)
npm run prepare        # regenerate monograms, favicons, proof logos, graded photos and og.jpg from the source files
npm run build          # production build (placeholders allowed)
npm run build:prod     # fails while any [placeholder] remains in CONTENT.md
```
Launch switches live in `site/src/content/site.ts` (BUILD-SPEC §14): `monogram`, `sampleMenuPdf`, `quotesEnabled`, `logosCleared`, `herbsEnabled`, `guests`, `courses`, `priceFrom`, `faq.leadTime`, `faq.cancellation`. All start in the "not received" position, so today the site ships: no Guests row, menu row without a course count, "Menu and proposal on request", no quotes, all eleven proof names set in type, no herb library, two FAQ rows instead of four.
Email needs `RESEND_API_KEY`, `ENQUIRY_TO`, `ENQUIRY_FROM` (see `site/.env.example`); without them the API route redirects to `/enquire?error=1`.

Fix applied: `site/node_modules` is now a symlink to `site/node_modules.nosync` (iCloud ignores `*.nosync`), reinstalled fresh. Rule from now on: never `rm` the symlink without recreating it; `npm install` works through it. The photos, `dist/` and `.astro/` can still be evicted; if a build hangs again with no output and 0% CPU, run `find . -flags +dataless | head` before anything else.
